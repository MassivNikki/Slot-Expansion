# Ideas for Slot Expansion

These are proposals, not features that already exist. They are meant as a
menu of directions to explore, not a plan to implement everything. Numbers,
rewards, and costs would need testing on a fresh save.

## A possible direction

Give each machine a personality: one might build steady income with reliable
small wins, while another chases rare combinations and spectacular bonus
rounds. The player expands a little casino, makes interesting choices for each
machine, and gradually discovers new ways for their machines to work together.

The current rules can remain the foundation: sevens start at 3% in every
column once unlocked, x2 appears only in interior columns, and the affected
machine allows no upgrade or stake changes during free spins. Other machines
remain usable.

## Machines and builds

### Machine specializations

After reaching a milestone, let the player choose a specialization for a
machine. For example:

- **Steady Eddie:** rewards frequent lower-tier wins and longer streaks.
- **Jackpot Hunter:** rewards rare high-tier combinations, but grows slowly
  between big wins.
- **Storm Chaser:** builds its strength around thunder symbols and free spins.

Give each path a different upgrade branch and visual identity. Make changing
specialization possible for a clear cost or after a reset, so experimenting
does not permanently ruin a machine.

### A different purpose for each new machine

Instead of later machines being only more expensive copies, introduce optional
machine types with a distinct twist. A **Forge** machine could charge a meter
with tier-one symbols; a **Garden** machine could improve its next few spins
after a series of wins. Existing machines could stay the simple, familiar
baseline. New types should have their own rules explained before purchase.

### Casino connections

Unlock a limited number of connections between machines. For example, every
so often one machine's wins could add charge to another machine's bonus meter.
Connections would encourage the player to think about their collection as a
whole, without making a new machine useless until every other machine is
upgraded. Show the source and effect of each connection in both machines.

### Grid expansion as a choice

Expanding the grid currently resets several upgrades and the pet. Make that
trade-off feel like a deliberate renovation: show exactly what resets, what
stays, and the new paylines before purchase. An optional later upgrade could
preserve one chosen category during the next expansion. This would give
players a reason to plan without hiding the cost.

### A small upgrade tree

Give each machine a few mutually exclusive upgrade branches rather than
endlessly increasing every number. For example, choose between improving
individual line payouts and building a bonus from multiple winning lines on
the same spin. Keep the tree small enough that the consequences fit in a
short explanation, and offer a way to reconsider the choice.

## Spins and special moments

### Bonus meters

Add a visible meter that fills from a specific event, such as a winning line
with three different winning paylines on one spin. When full, it guarantees a
clearly described bonus on the next eligible spin. This creates anticipation
even between lucky jackpots. Different machines could fill their meters in
different ways.

### A charged symbol

A new crystal symbol could collect charge when it appears and release the
stored bonus on a later qualifying win. Show the stored amount and what
triggers it. Unlike x2, it would be about building toward a payoff rather than
simply multiplying a line. Its interaction with paylines and grid expansion
would need an explicit rule.

### Free-spin themes

Before entering a bonus round, an equipped machine setting could select one of
several free-spin themes: more frequent small bonuses, a growing bonus meter,
or a single larger finish. The setting is chosen outside the round; during
free spins the player still only spins that machine. If another spin awards
additional free spins, show how they extend the same round.

### Collection boards

Give each machine a small board of symbol combinations to discover. Finding a
combination fills one space, and completing a row gives a modest permanent
reward or cosmetic. This makes unusual spins interesting even when their coin
payout is small. A board should never require a symbol the player cannot yet
unlock.

### Near-miss information without false promises

Show which paylines won and what each contributed, including the stake,
machine level, pet, and x2 effects. A highlighted non-winning line could
explain why it did not win, but should not imply that a past near miss makes
the next spin more likely to succeed.

## Progression and goals

### A casino roadmap

Add a compact list of upcoming milestones: the next machine, the next grid
expansion, and a few optional goals. Show current progress and the reward,
without requiring the player to hunt through every panel. This gives early
play a direction while leaving the player free to choose what to buy.

### Play-based contracts

Offer a few optional goals such as winning with three paylines on one spin,
using two different machines, or earning a certain amount from a particular
symbol. Replace a completed contract with another one chosen from the
player's unlocked content. Base progress on play, not a daily login timer;
avoid requiring long stretches of bad luck or a particular purchase order.

### A first-win tour

Introduce mechanics gradually through short, dismissible goals: make a spin,
unlock a symbol, inspect a payline, and buy an upgrade. Each goal could point
at the relevant control and explain *why* it matters. Let experienced players
skip the tour, and avoid locking ordinary controls behind it.

### Prestige as a later-game option

Eventually offer a voluntary casino renovation: reset ordinary machine
progress in exchange for a separate, permanent resource. Spend that resource
on new starting options, alternate machine types, or quality-of-life features,
not only a bigger multiplier. Before confirming, show every item that will
reset and every reward that will remain. This is a gameplay feature, separate
from resetting the development save after balancing changes.

### Offline progress, with clear limits

An optional offline summary could award a bounded amount based on previously
enabled auto-spin machines. Rather than simulate hours of individual spins,
calculate a conservative estimate and show the time counted, assumptions,
and rewards. Decide explicitly whether offline progress can grant XP, pets,
or free spins; do not silently change the odds or consume an unknown stake.

## Pets and collections

### Pets with distinct jobs

Alongside their existing payout and auto-cooldown effects, give some pets
small, readable specialties: filling a bonus meter, improving a contract
reward, or helping a particular machine type. A pet's description should show
the complete effect and which machine it is assigned to. Avoid a single pet
that is always the best choice.

### Duplicate pets become progress

Put discovered pets in a collection book. Extra copies could provide pet
fragments used to improve a favorite pet or unlock alternate appearances.
Keep the original pet when upgrading it, and display the cost and result
before spending fragments. This makes repeats useful without forcing the
player to give up a pet they like.

### Pet expeditions

Let an unassigned pet go on a short expedition measured in spins rather than
real-world time. When it returns, it could bring fragments, a cosmetic, or a
small amount of coins. The trade-off is that the pet cannot help a machine
while away. Show progress and allow the player to cancel without losing the
pet.

## Clarity and quality of life

### An upgrade preview

For each upgrade, show the current value, next value, price, and what the
change affects. For chance upgrades, also show which lower tier loses
probability. Explain why a button is disabled, such as insufficient coins,
a locked symbol, or the active free-spin restriction. This would make the
existing system easier to understand without changing its rules.

### A paytable and probability inspector

Add an in-game reference for symbols, paylines, free spins, and payout
calculation. A per-machine probability view could show current odds by
column, distinguishing permanent upgrades from temporary free-spin effects.
Keep the seven and edge-column x2 rules visible so players can understand why
columns differ.

### Machine overview

Add an overview that shows each machine's level, pet, last payout, free-spin
state, and next affordable upgrade. Selecting a machine could focus or
highlight its existing panel. This could make larger collections easier to
navigate without prescribing the user's preferred panel positioning or
requiring scrollbars.

### Useful feedback, not constant animation

Use restrained color and animation for milestones, bonus meters, and big
wins. Let players reduce or disable motion and sound independently. Important
information should also be readable as text, so a color or animation is
never the only way to understand a result.

### Player-controlled safety and saves

Offer an explicit new-game action with a confirmation describing what will
be erased. An optional manual export/import of a save could help players
keep a favorite run. Report invalid files clearly and leave the current save
untouched if import fails.

## Experiments worth trying first

1. **Upgrade preview:** makes the current game easier to learn and provides
   useful information for balancing everything else.
2. **Casino roadmap and play-based contracts:** add direction using existing
   symbols, paylines, machines, and upgrades before introducing new systems.
3. **Machine specializations:** prototype two small paths and see whether
   players enjoy making different builds.
4. **Bonus meter:** add one visible, deterministic goal between random wins,
   then evaluate whether it makes spins more exciting.

For each experiment, test a fresh run and check how it affects time to the
first grid expansion and second machine. Compare average results across
seeded runs as well as a few unlucky runs; make sure free spins, free
minimum-stake spins, pets, and higher stakes cannot accidentally create an
unbounded reward loop.

## Where implementation would start

The README's **Where to make changes** table is the best starting point for
the current architecture. In general, put gameplay rules in the machine
classes rather than Swing controls, keep player-visible state in the
appropriate machine or shared state, and update save/snapshot handling when a
new feature must persist. Consider the UI, save behavior, balance, and focused
tests together for each idea rather than building all systems at once.
